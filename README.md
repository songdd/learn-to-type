# 奕霖打字 · 项目详细设计文档
版本：1.0
日期：2026年6月18日
项目定位：一款专为儿童及打字初学者设计的互动式打字练习平台，通过趣味游戏与系统化课程，帮助用户掌握键盘指法，提升打字速度与准确率。

## 1. 项目概述
### 1.1 核心目标
教育性：提供从基础键位到全键盘的阶梯式打字课程。
趣味性：将打字练习融入飞机射击、打地鼠、警察抓小偷等游戏中，降低学习枯燥感。
文化性：融入古诗拼音练习与英文文章阅读，拓展学习维度。
数据驱动：通过本地存储记录学习进度与成绩，让成长可视化。
### 1.2 用户画像
主要用户：儿童、打字初学者。
次要用户：家长或教师（通过管理后台了解学习进度）

### 1.3 技术栈
前端：原生 HTML5, CSS3, Vanilla JavaScript (ES6+)。
存储：localStorage (用于保存用户进度、游戏记录、设置)。
配置：JSON 文件驱动 (config.json)。
多媒体：Web Audio API (生成简单音效)。

## 2. 系统架构
### 2.1 整体架构图
项目采用多页面应用（MPA） 架构，每个核心功能独立为一个HTML页面，通过URL参数进行状态传递，通过localStorage进行跨页面数据共享。

### 2.2 数据流
配置加载：所有页面启动时，首先异步加载 config.json，获取课程/关卡元数据。
用户认证：通过 login.html 验证邀请码，成功后写入 localStorage (logged_in, user_name)。
学习进度：关卡完成后，将关卡ID存入对应的 localStorage 键（如 typing_completed_basictype），实现进度持久化。
游戏成绩：游戏结束后，将详细成绩（得分、连击、用时）存入对应的历史记录键（如 plane_shooter_history）。

### 2.3 核心配置文件 (config.json)
此文件是系统的“大脑”，定义了所有课程和游戏关卡。其结构如下：
    根节点：learn-to-type (数组)。
    分组 (Group)：每个分组代表一个练习模块（如 basictype）。
        code: 模块唯一标识。
        name: 模块显示名称。
        levels: 该模块下的关卡数组。
    关卡 (Level)：
        id: 关卡唯一ID。
        description: 关卡描述。
        url: 对应的HTML页面。
        keys: 本关练习的键位数组（核心参数）。
        level: 难度（beginner/intermediate/advanced）。
        num: 练习字符数量或游戏目标数量。
        rate/maxDistance等：特定游戏的专属参数。

## 3. 功能模块设计
### 3.1 核心课程：基础打字练习 (basictype.html)
功能描述
提供循序渐进的字母输入练习，是平台最核心的学习路径。共52个关卡，从基准键（ASDF JKL;）逐步扩展到全键盘。
核心机制
    关卡驱动：
        通过URL参数（id, keys, level, num）或config.json定义关卡。
        根据 keys 参数生成练习文本，level 参数控制文本顺序（顺序/微乱/全乱）。

    交互方式：
        用户在下方输入框中依次输入字符。
        实时反馈：正确时输入框变绿并播放正确音效；错误时输入框抖动并播放错误音效。
        虚拟键盘：实时高亮当前需按的键位，辅助指法记忆。

    进度与统计：
        顶部状态栏显示准确率、用时、进度。
        通关后展示星级评价（⭐⭐⭐），并自动保存进度到 localStorage。

### 3.2 趣味游戏模块
#### 3.2.1 小飞机射击 (plane_shooter.html)

    核心玩法：屏幕上方的字母下落，用户敲对字母发射导弹击落目标。
    特色系统：
        连击系统：连续命中得分递增（5连击15分，10连击25分）。
        难度递进：30个关卡，通过 rate 参数控制字母下落速度。
        皮肤系统：5种战机外观可切换，数据保存在 localStorage。
    交互反馈：音效、爆炸粒子特效、得分浮动显示。

#### 3.2.2 打地鼠 (whackamole.html)

    核心玩法：地鼠从洞中冒出并举着字母牌，用户按对应字母击打。
    特色系统：
        多目标管理：随关卡提升，同时出现的地鼠数量增多，停留时间变短（由 rate 和 num 共同控制）。
        皮肤系统：5种小动物皮肤（🐭🐹🐰🐱🦊）。
        反馈特效：飞锤动画、击中得分浮动。
    关卡布局：设计了8种不同的洞位布局，随关卡ID循环变化，增加新鲜感。

#### 3.2.3 警察抓小偷 (catch_thief.html)

    核心玩法：警察与小偷在路径格子上移动，用户敲对字母，警察前进一格；若等待太久或敲错，小偷前进一格。
    特色系统：
        追逐机制：警察追上小偷前，距离不能超过 maxDistance 格，否则失败。
        动态难度：通过 rate 参数控制小偷自动前进的频率。
        双皮肤系统：警察和小偷可分别更换皮肤（警车/摩托车，小偷/一只耳）。
    交互反馈：角色移动时自动切换朝向图片，音效反馈。

### 3.3 文化拓展模块
#### 3.3.1 诗韵打字 (poetry_writing.html)

    核心玩法：展示古诗原文，用户需为每个汉字输入其对应的拼音（无声调）。
    交互机制：
        实时前缀匹配校验：输入拼音前缀时即时反馈对错。
        输入正确后自动跳转至下一个汉字，并高亮显示已完成的字。
    内容：内置30首经典古诗（五言/七言），包含作者、朝代、逐字拼音数据。

### 3.3.2 英文文章练习 (english_typing.html)

    核心玩法：展示英文文章原文，用户需在下方输入框中完整输入每个单词。
    交互机制：
        单词级实时校验：输入单词前缀时即时反馈，输入完整单词且正确后自动提交。
        原文与输入区域上下对照，当前目标单词高亮显示。
    统计：除准确率、用时外，增加WPM（每分钟单词数）指标。
    内容：内置30篇英文短文，按难度分级（入门/进阶/高级/专家）。

## 3.4 导航与管理模块
### 3.4.1 主页 (index.html)

    功能：全局导航中心，展示核心亮点、课程/游戏/诗词/文章的快捷入口，以及用户学习报告概览。
    数据聚合：从 localStorage 读取所有模块的完成度、总得分、最高连击，在仪表盘汇总展示。

### 3.4.2 列表页 (courses.html, games.html, poetry.html, literature.html)

    功能：展示对应模块的全部关卡/列表，并显示每个项目的完成状态（✅ 已通关/📖 未学习）。
    数据来源：读取 config.json 渲染列表，读取 localStorage 渲染状态。

### 3.4.3 登录系统 (login.html)

    核心流程：
        用户输入邀请码。
        前端发送 POST /api/verify 请求至后端验证。
        验证通过后，前端记录登录状态，并发送 POST /api/login-log 记录登录日志。
        跳转至主页。
    辅助功能：展示抖音/微信二维码，引导用户获取邀请码。

### 3.4.4 管理后台 (admin.html)

    功能：用于管理和查看邀请码与登录记录。
    核心操作：
        生成邀请码：输入好友名称和抖音号，生成唯一邀请码并存入数据库。
        邀请码列表：支持筛选（状态、名称）、分页、复制链接、删除。
        登录记录：展示所有登录历史，支持按用户、邀请码、日期筛选，并支持导出CSV。

    数据交互：完全依赖后端API（/api/get-invites, /api/add-invite, /api/login-logs等）。

# 4. 数据存储设计

所有数据均存储在客户端的 localStorage 中。
Key	作用	数据结构示例
logged_in	登录状态	"true"
user_name	用户名	"张潇"
typing_completed_{code}	各模块通关记录	[1, 3, 5, 7] (已通关的关卡ID数组)
{code}_history	各游戏模块的详细成绩	{"1": {"score": 150, "maxCombo": 12, "time": 35}} (关卡ID为键的对象)
{skin_key}	游戏皮肤设置	"🐭" 或 "police_car"
catch_thief_history	抓小偷模块历史记录	{"1": {"score": 10, "maxCombo": 5, "time": 20}}
# 5. 用户界面与体验 (UI/UX)
## 5.1 设计语言

    整体风格：圆润、柔和、色彩明亮，大量使用渐变、圆角、毛玻璃效果（backdrop-filter: blur()），营造友好、卡通的氛围。
    字体：优先使用 Comic Neue 和 Comic Sans MS 等圆体字，贴合儿童用户群体。
    反馈：通过丰富的动画（抖动、缩放、弹窗、粒子特效）、音效和即时文字提示，为每一次操作提供清晰反馈。

## 5.2 响应式设计

    使用 flexbox 和 grid 布局。
    通过 clamp() 函数和 @media 查询，适配从手机到桌面端的各种屏幕尺寸。
    游戏画布（Canvas）会随容器大小动态调整。

# 6. 开发规范与部署
## 6.1 代码组织

    页面独立：每个HTML文件为一个独立页面，包含其完整的样式和逻辑，降低耦合度。
    配置集中：所有课程和关卡数据集中在 config.json，便于内容更新和维护。
    资源管理：图片等静态资源统一放在 pic/ 目录下。

## 6.2 部署
    静态托管：由于主要是前端静态页面，可部署在任何支持静态文件托管的服务上（如 GitHub Pages, Vercel, Netlify）。
    后端服务：管理后台（admin.html）的API功能需要单独的后端服务支持（如Node.js/Deno），项目中 edge-functions/api 目录暗示了可能使用了边缘计算或Serverless函数来处理API请求。

## 6.3 待优化与注意点

音效初始化：部分页面的音效需要用户首次点击/按键后才可启用，这是浏览器自动播放策略的限制，属于正常设计。
API依赖：登录和管理后台功能强依赖后端API，在纯前端环境下无法完整工作。
数据隔离：localStorage 按域名隔离，不同设备或浏览器间数据不互通。
代码复用：多个游戏页面中存在相似的UI样式（如头部导航、历史记录弹窗）和逻辑（如音效生成、进度保存），后续可考虑抽取为公共组件或工具库。
